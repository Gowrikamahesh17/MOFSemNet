# Progress logs

Dated entries written after each work session, later stitched together into the final thesis
report. This folder holds the raw material, not the report itself.

## Convention

- One file per work session: `reports/logs/YYYY-MM-DD-<short-topic>.md`
  (e.g. `reports/logs/2026-09-21-project-scaffold.md`).
- Copy `reports/templates/log_entry_template.md` as the starting point for each new entry.
- Write it at the end of the session it describes, not days later — the point is to capture
  what was actually decided/found while it's still fresh, not to reconstruct it from memory.
- Don't edit past entries to "clean them up" after the fact; if a decision recorded in an old
  entry turned out to be wrong, say so in a *new* entry and link back to it. The log is a
  record of what was known/decided at the time, not a living document.

## From logs to report

When it's time to write the actual thesis report, pull from these entries rather than trying to
remember six months of work — that's the entire reason they exist.
